JD3 COLORPICKER — Updated PangoScript package
================================================

This package adds *per-channel snap during swap-fade* plus two niceties:
1) End the fade early if both channels are snapped mid-fade.
2) Reset the swap “session” after any manual color/off selection so the next Swap starts fresh.

Install steps
-------------
1) In your COLORPICKER universe, create **four** hidden helper objects (any control that exposes a .Tag is fine; Number, Label, or Button with visibility off):
   - SWAP_FADEACTIVE   (Tag default 0)
   - SWAP_HOLD0        (Tag default 0)  // hold Primary (channel 0)
   - SWAP_HOLD1        (Tag default 0)  // hold Secondary (channel 1)
   - SWAP_RESETSESSION (Tag default 0)

2) Replace the code on these UI elements with the files from this zip:
   - SWAPCOLOR BUTTON WITH FADE REVERSE.txt  (Swap button)
   - SWAPMODE BUTTON CODE.txt                (Swap mode toggle)  [unchanged]
   - All *BUTTON1 CODE.txt files (Primary colors)
   - All *BUTTON2 CODE.txt files (Secondary colors)

3) No changes required for Pastel, Monochrome, or SAT controls.

What changed
------------
- During a running FADE swap:
  • Selecting a **Primary** color (or toggling it Off/black) sets `SWAP_HOLD0.Tag = 1`.
  • Selecting a **Secondary** color (or Off) sets `SWAP_HOLD1.Tag = 1`.
  • The fade loop respects these holds: the held channel **stops being updated** and stays snapped; the other channel **keeps fading**.
  • If both channels are held, the fade completes early.

- Any manual color/off selection sets `SWAP_RESETSESSION.Tag = 1`.
  • The next time you press **Swap**, the script discards the previous A/B endpoints and starts a **new session** from the current colors.

Notes
-----
- SNAP mode is unchanged.
- Reverse-on-press-during-fade is preserved via the existing SWAPCOUNTER logic.
- Monochrome mode remains unaffected.
