# PangoLint Data Layout Policy

Issue #519 records the data layout plan for the public packaging and MCP
control-reference rollout tracked by #520. This plan is a contract for future
file moves. It does not move active data by itself.

## Public Checkout Rule

Normal public development, tests, VSIX package verification, and MCP package
verification must run from tracked files after `npm ci`.

The public repo does not include maintainer refresh scripts for local research
material. Normal public gates read checked-in data.

## Target Layout

The target layout keeps source data, generated package data, maintainer input,
and local artifacts separate.

| Target path | Intended role | First issue that may change it |
| --- | --- | --- |
| `data/pangoscript/` | Shared tracked data for extension runtime, MCP lookup, reference-site input, and tests | Existing source path |
| `data/pangoscript/control-reference/` | Full tracked control-reference source for docs, reference UI planning, and compact projection generation | Existing source path |
| `data/pangoscript/control-reference/mcp-control-reference/` | Compact MCP control-reference projection generated from tracked data | #517 |
| `docs/references/` | Human reference docs and generated command-reference markdown | Existing source path |
| `media/reference/` | Generated offline reference site output for the VSIX | Existing generated output |
| `mcp/data/` and `mcp/docs/` | Ignored MCP tarball staging copied from approved root files | #518 package trimming |
| Maintainer-only research material | Outside the public repository | #515 path policy |

## Proposed Move Plan

No active files move in #519. Future move PRs must use this order:

1. Add or update the replacement path.
2. Move the active consumer to the replacement path.
3. Update scripts, tests, docs, `.vscodeignore`, `scripts/package/copyMcpData.cjs`, and `scripts/package/verifyPackageContents.ts`.
4. Run the validation commands named below.
5. Only then remove the old file or folder.

Proposed future moves:

| Current path | Replacement path | Move class | Required consumer updates |
| --- | --- | --- | --- |
| Full MCP copy of `data/pangoscript/control-reference/` | `data/pangoscript/control-reference/mcp-control-reference/property-controls.json` | Active generated data to MCP lookup data | Done in #517 and #518. Keep MCP package tests and tarball verification locked to the compact projection. |
| Redundant full control-reference JSONL files in the MCP package | Compact MCP projection under `data/pangoscript/control-reference/mcp-control-reference/` | Active package input to compact package input | Done in #518 package tests and tarball contents. |
| Any stale local research file | Remove once no public command reads it | Research input to retired historical file | None for public gates. |
| Any tracked Object Tree evidence group no longer read by generators or tests | Remove after replacement source facts and tests are in place | Maintainer-only evidence to retired historical file | Generator source paths, data tests, package verification, and issue body must prove it is unused. |
| Any old docs plan that no longer reflects shipped behavior | Remove or replace with a short public summary in `docs/runbooks/` | Retired historical file | Link checks, docs tests, README/manual references. |

## Retirement Rules

- Do not remove active extension runtime data, MCP lookup data, reference-site
  input, generated docs data, scripts, or tests until the replacement path is
  present and validated.
- The PR or issue must name the original path, reason, replacement path,
  date, and validation commands.
- Keep maintainer-only evidence out of packages.
- Public package verification must fail if maintainer-only local material
  enters the VSIX or MCP tarball.

## Validation Commands

Use the narrowest relevant commands during a move, then the full gate before
merge:

```bash
npm run build:knowledge
npm run verify:package
npm --workspace mcp run verify:tarball
npm run check
```

For tracked-files-only verification, use a clean worktree or clean clone, then
run:

```bash
npm ci
npm run check
```
